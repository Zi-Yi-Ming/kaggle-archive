# Solar Filament — 太阳暗条分割（Playground S6E6）

## 比赛简介

Kaggle Playground Series Season 6 Episode 6：太阳暗条（solar filament）图像分割。

- **类型**: Playground（无奖牌）
- **数据**: MAGFiLO 1.0，COCO polygon 标注，2048×2048 灰度图，**仅 19 张训练图**（极小样本分割）
- **目标**: 多类分割（3 类 filament），二值化基线对比

## 核心挑战

**19 张训练图的极小样本分割** —— 这是本赛最大的难点：
- 直接全图训练极易过拟合
- 需要 patch 切片扩样 + 轻量网络 + 混合损失

## 方法

### `solar_v1_unet.py` — U-Net baseline
- 纯 torch 手写轻量 U-Net（无 torchvision/SMP 依赖，本地 CPU 可冒烟）
- 2048² 大图切 **512×512 patch**（每图多 patch 扩样）
- 4 类 filament 合并为二值前景
- 损失：**Dice + BCE 混合**（缓解类别不平衡）
- 本地冒烟：`python solar_v1_unet.py --smoke`；完整训练：`--epochs 30 --patch 512`

### `multiclass_quick.py` — 二值 vs 多类对比
- 3 类 mask（每类一通道）vs 二值 mask 的快速 CPU 冒烟对比
- 验证多类学习是否有增益

### `patch_exp.py` — patch 大小实验
- 对比 128 / 256 patch 的训练信号密度
- 附带 filament 占比分析（`pos_ratio`）

## 实验结果

- 二值 Dice/BCE U-Net 为最终基线
- 多类与二值的差异在 19 图小样本下不显著（CPU 冒烟验证，未跑完整 GPU 训练）

## 复盘

1. **极小样本下 patch 切片是唯一可行的扩样手段**，512 patch 兼顾信号密度与感受野
2. **Dice+BCE 混合损失** 对暗条这种细长稀疏目标（filament 占比常 <5%）比纯 BCE 稳定
3. 该赛定位为 U-Net 分割练手场，未冲榜（Playground 无奖牌），代码沉淀了可复用的纯 torch 分割模板

## 状态

✅ 完赛（无奖牌练习赛，U-Net 分割模板沉淀）

# 🧠 深度复盘(2026 完赛归档)

## 1. 心理历程:19 张图,怎么让模型学会"看"暗条

这是我第一次打图像分割赛,拿到数据的第一反应是懵的:**只有 19 张训练图**,
而且每张 2048×2048、目标是细长稀疏的太阳暗条(filament 占比常 <5%)。
当时的核心焦虑是"这么点数据怎么训练?"——答案几乎是被逼出来的:**patch 切片**。
2048² 的大图切成 512×512 的小块,每图出多个 patch,19 张图瞬间扩成几百个
训练样本。这是极小样本分割唯一可行的扩样手段。

第二个决策是**不引入重型依赖**。当时我在 RSNA(医学影像)上有 GPU 额度焦虑,
习惯了"本地 CPU 先冒烟、Kaggle GPU 再全量"的工作流。所以 U-Net 用纯 torch
手写(无 torchvision/SMP),损失用 Dice+BCE 混合——本地 CPU 就能跑通整条管道,
这在当时是最务实的选择(Playground 无奖牌,不值得为它配 SMP 环境)。

之后做了两个探索实验:多类(3 类)vs 二值对比(验证细分类是否有增益)、
patch 128/256 大小实验(验证训练信号密度)。结论都是**19 图小样本下差异不显著**
——样本量不够,模型复杂度/类别细分的红利根本显现不出来。于是停在二值
Dice/BCE U-Net 作为最终基线,未跑完整 GPU 训练,未冲榜。

**定位反思**:这个赛的价值不在分数,而在于把"纯 torch U-Net + patch 切片 +
Dice/BCE"这套模板跑通并沉淀——它是我从"表格/分类"进入"图像分割"的第一块
地基,后续真实分割类任务可以直接复用。

## 2. 架构方法演变:极小样本下的务实链路

```
数据:19 张 2048² 灰度图 + COCO polygon 标注(太阳暗条,占比常 <5%)
 │  ↓ 扩样:patch 切片 512²(每图多 patch)
v1 纯 torch U-Net + Dice/BCE (最终基线)
 │  ├ 二值化:4 类 filament 合并为前景(细分类在 19 图上不显著)
 │  ├ 轻量 U-Net(无 torchvision/SMP,本地 CPU 可冒烟)
 │  └ Dice+BCE 混合损失(细长稀疏目标的稳健选择)
 ├── multiclass_quick:3 类 vs 二值对比(CPU 冒烟,差异不显著)
 └── patch_exp:128/256 patch 信号密度实验
```

**设计动机**:样本量决定一切——19 图只够撑起"二值 + 单网络 + patch 扩样"
这条最省样本的链路;细分类、大 patch、重型网络都是样本不够时的奢侈品。

## 3. 失败/探索实验档案

| 实验 | 结果 | 教训 |
|---|---|---|
| 3 类 vs 二值(CPU 冒烟) | 差异不显著 | 19 图下类别细分红利显现不出来 |
| patch 128/256/512 对比 | 512 兼顾信号与感受野 | 大 patch 保留空间上下文,小 patch 信号更纯 |
| 全图 2048² 直接训练 | 不可行(内存/样本) | 极小样本必须 patch 扩样 |

## 4. 核心经验教训(武器库)

1. **极小样本分割的第一课 = patch 切片扩样**:19 图切成数百 patch 才能训练
2. **细长稀疏目标用 Dice+BCE**:filament 占比 <5%,纯 BCE 会被背景淹没
3. **纯 torch 手写 U-Net = 可移植模板**:无重依赖,CPU 冒烟 → GPU 全量,
   后续真实分割赛可直接复用这条管道
4. **样本量决定模型复杂度上限**:19 图时二值单网络是上限,别上细分类/大网络
5. 分割模板沉淀的优先级 > Playground 冲榜(无奖牌赛的正确用法是练管道)
